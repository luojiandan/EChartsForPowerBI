# C020 多风格日历热力图｜案例说明

> **技术名称：** C020_多风格日历热力图  
> **传播名称：** Power BI 日历热力图：一份数据，两种方式看懂全年变化  
> **包含风格：** 标准月历热力图（Standard Calendar Heatmap）、GitHub 风格日历热力图（GitHub-style Calendar Heatmap）

## 一、案例简介

日历热力图将**每一天映射为一个色块**，通过颜色深浅或冷暖变化呈现全年数据的分布。与传统折线图强调连续涨跌不同，它更适合寻找**季节规律、日期集中区间与异常日期**。

本案例以**2025 年西安逐日最高气温**为演示主题，采用同一份 **365 天模拟数据**，制作两种风格：

- **标准月历热力图：** 按 12 个月分组，每个月采用传统日历结构（星期为列、周次为行），便于查看具体日期及比较月内分布；月份标题右侧显示当前筛选范围内的天数。
- **GitHub 风格日历热力图：** 按全年连续周次横向排列，星期纵向排列，通过阶梯分隔线标示月份边界，突出全年连续性和季节变化；不重复显示各月天数。

两种风格均支持拖动连续色阶筛选数值区间，图中高亮匹配日期，右上角同步显示当前区间与全年符合条件的天数；鼠标悬停日期可查看具体日期与指标值。

**数据口径：** 演示指标为日最高气温，单位为 ℃。当前数据是**为图表开发构造的模拟数据，不是西安气象观测实测值，也不是 Open-Meteo 历史数据下载结果**；不可据此发布真实气温结论。正式应用须替换为可核验的逐日数据，并同步修改图表标题、指标单位及来源说明。

## 二、核心技术原理

**1. 平行数组与日期自动处理**  
原始输入只需 `dates[]`（日期）和 `values[]`（指标值）两个等长的一维数组。程序校验日期、数值与重复记录，自动识别年份、闰年、每月天数及星期位置；内部再生成 ECharts 所需的数据对象。可用于将 Power BI 字段直接映射到数组，无须为不同年份逐一修改月份布局。

**2. 两种日历的布局计算**  
通过 ECharts `custom series` 的 `renderItem` 绘制每日矩形。标准月历在每个月内按星期列与周次行组织，并按容器宽高计算月份组排列、日期格大小和间距；GitHub 风格则依据全年起始星期计算连续周索引，再动态放置月份标签与阶梯边界。两种布局代码独立，使用相同的数据结构。

**3. 连续色阶与区间筛选**  
使用 `visualMap` 的连续型色阶（`type: 'continuous'`）映射指标大小，支持默认自动范围与手动指定范围，拖动两端手柄选择数值区间。选中范围内的日期保留色彩，范围外日期弱化，便于发现特定温度区间或异常高值集中在哪些天。

**4. 区间天数实时统计**  
根据当前筛选区间，逐日统计满足条件的**有效数据天数**，统计时包含上下边界，不计缺失值。通过 `datarangeselected` 等事件联动更新：标准月历展示每月与全年统计，GitHub 风格只展示全年统计。图例悬停预览与拖动持久选区属于不同状态，实际部署时需将事件监听绑定至当前 ECharts 实例。

**5. HTML Tooltip 与通用配置**  
Tooltip 显示日期、星期、指标名称及数值，采用高对比度样式与边界避让策略。标题、单位、字体、色阶、网格间距、响应式布局、统计开关等设置集中在前置 `setting` 中；图形处理不绑定“西安”或特定年份。

## 三、适用场景

- **气象与环境：** 每日最高气温、降雨量、空气质量等，识别季节变化和集中异常日期。
- **企业经营：** 每日销售额、订单量、门店客流，观察工作日、周末及节假日分布。
- **运营与用户活跃：** 每日访问量、登录人数、任务完成数，分析活跃周期及低活跃时段。
- **生产与设备监控：** 每日产量、故障次数、停机时长，发现异常高发日期。
- **金融与市场观察：** 每日涨跌幅、交易量、波动指标，比较全年市场活动的分布特征。

**使用提示：** 两种风格为同一案例的独立模板，实际使用时选择其一即可。数据可以是不完整年度，但日期应可解析、每个日期不重复；筛选天数仅针对存在有效数值的日期。当前示例数值均为模拟数据。
