## 一、案例简介

本案例面向 **ECharts for Power BI**，利用 ECharts `custom series`，在**同一个金额纵轴**下组合**季度营收柱状图**和**年内累计营收阶梯线**。柱体用于比较不同类别的单期经营规模，阶梯线用于观察同一类别随时间逐步累加的规模；同组采用统一色系，适合回答“哪些类别收入更高、哪一期出现增长或下降、截至本期累计达到多少”。

演示采用 **Apple 2025 财年** Mac、iPad、可穿戴及家居配件三类业务的季度营收，共 **3 类 × 4 季度 = 12 条**真实数据。原始财报单位为**百万美元**，案例按 `÷100` 换算成**亿美元**。三类年度营收分别为 **337.08、280.23、356.86 亿美元**；这三类仅是 Apple 的部分业务，**不能将其合计解释为 Apple 公司总营收**。2025 财年截至 **2025 年 9 月 27 日**，不是自然年度。

**读图结论：** 这三类业务在 FY2025 Q2 均较 Q1 下滑。其中，可穿戴及家居配件由 117.47 亿美元降至 75.22 亿美元，季度环比约 **▼36.0%**，跌幅最大。后续季度部分回升，但累计收入因非负季度收入逐期增加而持续上升。需要区别“季度收入的增长”与“累计收入的增长”，它们不是同一个指标。

- [Apple 2025 财年 Q2 Form 10-Q（截至 2025-03-29）](https://www.sec.gov/Archives/edgar/data/320193/000032019325000057/aapl-20250329.htm)

## 二、核心技术原理

1. **三个平行的一维数组。** 原始输入固定为 `类别`、`季度`、`营收`，同一索引代表同一条观测记录；演示数据各有12项。替换成 Power BI 字段时，将数组赋值为实际字段槽位对应的 `dataArr.dataObjects[i].values` 即可，**实际索引须按视觉对象的字段顺序核实**；不要把累计金额或环比作为额外输入列。
2. **任意类别数及周期数。** JS 从数据自动识别类别和周期，按类别独立组织时序；默认对周期名进行数字自然排序，也可以通过 `setting.periods` 指定顺序。每个类别必须有完全一致的周期集合，且每个“类别×周期”仅有一条有效记录，否则报错。类别可以是商品、区域、部门、渠道，周期也可以是季度、月份或阶段，不局限于当前的3类4季。
3. **季度环比自动计算。** 除第一个周期外，`环比 = (本期金额 - 上期金额) / 上期金额 × 100%`。增长统一使用绿色 `▲`，下降使用红色 `▼`，零变化显示中性标注；前一期为0时环比不可定义，Tooltip 不伪造数值。标签在空间不足时有条件隐藏，但计算结果仍可通过 Tooltip 查看。
4. **年内累计及共轴阶梯。** `截至本期累计 = 从首期到本期的金额之和`；每个类别独立累计，**不同类别的阶梯线不相连**。阶梯与柱体共用同一纵轴，因此二者高度差表示真实金额尺度上的区别。默认从第2期开始显示累计金额，首期累计与首期柱体金额重复，不重复标注。
5. **单图自定义图元与响应式布局。** 使用 ECharts `custom series` 的 `renderItem` 绘制渐变柱、水平连接、垂直累计增量、节点、类别分界线、金额与环比标签。`grid` 上下左右边距采用像素；绘制阶段读取实际绘图区坐标和类目带宽，随 ECharts `resize()` 自动重新计算柱宽、组间距与标签密度。5类、8类等更多数据可使用同一代码，但较窄容器中会自动隐藏部分常驻标签，完整信息依赖 Tooltip。
6. **Tooltip 双占比与通用配置。** 白底富文本 Tooltip 显示单期营收、较上期变化、截至本期累计、本期占本类别合计、累计占本类别合计。两项占比的分母均为**该类别在当前输入的全部周期中的金额合计**，不是全部类别的总和；末期累计占比为100%是该定义的数学结果。`setting` 统一管理标题、副标题、统计期间标签、类别和周期名称、指标名称、单位、配色、数字精度及来源说明。**替换业务数据时必须同步更新 `setting.sourceText` 和计量单位，避免将新数据错误标注为 Apple 财报。**

**Power BI 字段替换示例：**

```javascript
// 字段槽位索引为示例，实际以视觉对象的数据绑定顺序为准
var 类别 = dataArr.dataObjects[0].values;
var 季度 = dataArr.dataObjects[1].values;
var 营收 = dataArr.dataObjects[2].values;

// 可在 setting 中按实际业务修改：
// categoryLabel: '区域', periodLabel: '月', metricName: '销售额', unit: '万元'
// periods: ['1月', '2月', '3月', '4月']
// fiscalYear: '2026年', sourceText: '数据来源：内部销售系统'
```

**适用边界：** 输入数值必须为非负有限数，每个类别在所选周期内合计必须大于0，适合营收、销量、订单数等**可累加**指标；不得直接用环比率、毛利率等比例型指标进行累计。类目过多、周期过长或容器极窄时，标签可能被有条件省略；业务文本也可能截断，建议依赖 Tooltip，并适当扩大视觉对象宽度。

## 三、适用场景

- **多产品线经营：** 比较产品、品牌、SKU 各期销售额，以及截至当期的年度累计收入。
- **区域或门店业绩：** 按不同区域、门店独立绘制季度/月度收入与累计值，寻找共同波动周期。
- **渠道销售分析：** 对比线上渠道、线下渠道及分销渠道的单期贡献和累计经营规模。
- **订单及业务量跟踪：** 将 `metricName` 切换为订单数、出货量等可累加指标，观察当期变化与累计进展。
- **预算执行进度：** 若使用分期实际执行额，可将其按期累加；但预算完成率应另行设定目标基数，不应误用本模板的“累计占所选期合计”指标。

**推荐读图顺序：** 先比较各组柱体的当期金额 → 再看 `▲/▼` 环比方向与幅度 → 沿阶梯线查看累计金额 → 最后悬浮 Tooltip 读取完整金额及两个占比。不同类别的累计金额可以比较，**同一类别累计必然随非负当期值不减，不等于业绩持续环比增长**。
